# Improvement Deep-Dive — NostrDanish/omarchy-mobile — 2026-10-21

Native Omarchy on Pixel (mainline kernel + Arch Linux ARM root + LineageOS-based tooling). `bin/omamobile` (flash/push/kexec with slot-B storage-guard), `rootfs/build-inside` (image assembly), `packages/omamobile-omarchy/bin/omamobile-update` (phone-side wrapper for `omarchy update`).

## Top recommendations (ranked, with effort S/M/L)

1. **[M] Channel switching on the phone is unguarded — shim or replace `omarchy-channel-set`.** Verified: the phone's pacman.conf is built with `@OMARCHY_CHANNEL@` substituted once at image-build time (`rootfs/pacman.conf` → `https://pkgs.omarchy.org/<channel>/$arch`), and `omamobile-update`'s stand-in dir (`packages/omamobile-omarchy/lib/update-bin/`) shims `omarchy-migrate`, `omarchy-snapshot`, `omarchy-update-*` and `sudo` — but **not** `omarchy-channel-set`. Upstream's channel-set ships with the `omarchy` package on the phone and, if run, would rewrite /etc/pacman.conf from *desktop* templates (no `[omamobile]` first, no phone ordering) and run a downgrade-capable `-Syyuu`. After that, `omamobile-update`'s `repository_order()` check refuses all updates until hand-repaired — a soft-brick of the update path. Fixes, cheapest first:
   - Add an `omarchy-channel-set` stand-in to `update-bin` that refuses with "channels are set at image build time on the phone" (S).
   - Or, if phone channel switching is wanted: an `omamobile-channel-set` that rewrites only the channel path segment in the `[omarchy]` Server line and then runs `pacman -Syy` — required because pacman keys sync DBs by *repo name*, not URL, so a URL swap without a force-refresh silently keeps serving the old channel's `omarchy.db` (M).
   - Also pull upstream omacom/omarchy#15903's `--ignore omarchy-dev,omarchy-settings-dev` lesson into any phone-side downgrade-capable transaction: the phone tracks `[omarchy]` stable by default, so an edge experiment + switch back hits the same stale-DB downgrade trap.
2. **[S] `RELEASE_NOTES` points at the old org.** `omamobile-update` uses `https://github.com/basecamp/omarchy/releases/latest` — upstream moved to `omacom/omarchy`. Redirects currently work, but fix the constant (and grep for other `basecamp/omarchy` references) (S).
3. **[S] No CI.** Root has `tests/` and per-package `test/` dirs (e.g. `packages/omamobile-mirror/test`, `omamobile-omarchy/test`) but no `.github/workflows`. A shell/python syntax + unit gate (`bash -n bin/* tools/*`, `python3 -m py_compile`, run the package test suites) is cheap and would have caught any broken-main (S). Add gitleaks while at it — this repo handles device provisioning scripts.
4. **[S] Branch protection**: all branches unprotected (verified). Protect `main`, require the CI from (3) (S).

- Build-time pins are mostly hash-pinned already — good: Alpine minirootfs `3.24.2` with hardcoded sha256 in `bin/omamobile` (verify 3.24 is still the current stable line when next bumping; check for a 3.25/3.26 minirootfs and update `ver` + `sum` together) (S).

## Missing gates (CI/tests/protection)

- Covered in #3/#4 above: no CI, no protection. The repo's own AGENTS.md/CONTRIBUTING.md are extensive (30 KB+) — wire their stated rules (e.g. descriptor KEY=value validation, storage-guard invariants) into an automated test run; `bin/omamobile initramfs-config` without args is already a validator and can run in CI without hardware (S).

## Quick wins (code/config)

- `bin/omamobile` copies **all** of `$HOME/.ssh/*.pub` into the initramfs `authorized_keys` — convenient but over-broad; document loudly or gate behind a config key (`SSH_PUBKEY_GLOB`) (S).
- `cmd_push`/`cmd_flash` are careful (verify-after-write, boot-id check) — nice. Add the same sha256-verify to the `kexec` path's streamed files (currently no checksum after `cat >` streaming) (S).
- `rootfs/build-inside` copies `cp /var/lib/pacman/sync/*.db "$T/..."` with `|| true` — a silently skipped DB copy produces an image whose first `omarchy update` force-refreshes anyway; log loudly when it doesn't happen (S).
- `tools/` mixes Python and bash with no extension on most files — a `file`-based lint in CI covers both (S).
